# OpenTeleCRM — Risk Register

Living risk register for the OpenTeleCRM monorepo. Likelihood/Impact: **L**ow / **M**edium / **H**igh. Review on every build wave (A1–A8) and before any release cut. Ties back to ADRs in [docs/DECISIONS.md](DECISIONS.md).

## Top risks

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| **WhatsApp ToS violation / number ban** — unofficial driver (whatsapp-web.js / Puppeteer) violates Meta ToS; number bans, business WhatsApp outage | High (any operator using unofficial driver at volume) | High (channel loss, brand damage, customer comms cut) | Dual-driver architecture (ADR-0015): Cloud API default for production; unofficial driver gated behind **mandatory per-enterprise consent modal** recording ToS/ban acknowledgment in `audit_log`; rate limiting (`ASYNC_RATE_LIMIT_PER_HOUR`); ban detection (message failure-rate alarms) with auto-pause; docs state ban risk is operator's, not OpenTeleCRM's |
| **Meta per-message fees** — Cloud API bills per message (marketing/utility tiers); costs explode at telecalling volumes | High (Cloud API is default prod driver) | Medium (unit economics per lead) | Fee telemetry per enterprise (ClickHouse, ADR-0005); pricing surfaced in admin UI; per-enterprise driver switch (unofficial driver available where operator accepts ToS risk); template cost guardrails — marketing-tier templates require explicit enablement |
| **Android 10+ SIM-call recording limitation** — OS blocks microphone access to call audio for SIM calls; recordings silent/missing | High (all modern Android) | Medium-High (core telecalling feature degraded) | **SIP/Asterisk is the recorded path**: calls route via SIP client → Asterisk (`infra/asterisk/`, `WITH_TELEPHONY=1`) records server-side; app only shows call state + control. SIM-call mode documented as record-less (CDR only). Do not attempt root/CALL_RECORDING_AUDIO workarounds — Play policy + OEM fragmentation risk |
| **Massive build surface (A1–A8)** — 10 service scaffolds + 10 packages + 4 apps (web/mobile/widget/extension) = huge parallel build wave; integration whack-a-mole | High (by design) | High (delivery stall, integration debt) | Wave ordering + contract tests as gate (API contract tests 6/6 green); shared `packages/db` + `core-domain` built first (Turbo `^build` graph); per-service smoke tests mandatory before wave sign-off; feature-flag kill switches (ADR-0014) let unfinished services ship dark; dependency guard: services must not import unowned packages |
| **AGPL/BSL license leaks** — a dependency or bundled artifact with AGPL/BSL/Sustainable-Use/CPML license contaminates the FOSS distribution | Medium (drift via new deps) | High (legal exposure, product can't be distributed as FOSS) | License allowlist in CI (license-checker on every PR): **rejected** — MinIO-as-default (ADR-0010), Redis ≥7.4 RSALv2 (ADR-0006), n8n Sustainable Use (ADR-0020), Metabase AGPL (ADR-0021), Dragonfly BSL, Flagsmith BSL, Coqui XTTS CPML default (ADR-0018 opt-in only), pyannote gated checkpoints (ADR-0016); audit on every dependency bump; release-artifact scan excludes opt-in checkpoints |
| **Air-gap LLM quality on 8vCPU** — small local models (7–14B quantized) underperform for call summaries / voice agent / lead scoring vs TeleCRM's cloud LLMs | Medium-High | Medium (feature quality, agent trust) | Model tiering: small fast models for realtime (voice agent, ADR-0017) + larger batch models for async summaries (BullMQ jobs, ADR-0006); prompt+few-shot tuned per tier; quality gate per wave with recorded transcripts as eval set; graceful degradation to rule-based extraction when confidence low; hardware upgrade path documented (GPU node optional) |
| **TeleCRM API drift** — upstream TeleCRM changes endpoints/schemas; 1:1 parity promise erodes | Medium (upstream evolves) | Medium (integration breakage for parity consumers) | Contract tests pinning current shapes (`metadata.contract.test.ts`); snapshot fixtures of TeleCRM responses captured via the reference MCP token (TeleCRM.mcp); changelog watch + quarterly parity re-check; versioned parity report per wave |
| **Subagent build-wave timeouts** — parallel subagent builds exceed session/tool timeouts, leaving half-built services | High (observed pattern in wave execution) | Medium (orphaned scaffolds, lost work, rework) | Build waves split into subagent-sized units with explicit finish criteria (build + smoke test, not "best effort"); Turbo caching so partial builds resume cheaply; ownership matrix + agent-coordination skill; each wave writes a status ADR-adjacent note before ending; no orphaned `package.json` without a smoke test |

## Additional risks

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| **Live TeleCRM MCP token committed** (`TeleCRM.mcp` contains a real `mcp_*` token) | Certain (already in repo, no commits yet) | Medium (credential exposure if repo is published) | Rotate the token against TeleCRM; gitignore or encrypt `TeleCRM.mcp` (keep only a redacted example); scrub before first public commit; treat any prior sharing as compromised |
| **Zitadel OIDC shim not upgraded** — `auth.guard.ts` OIDC path decodes without JWKS verification; if Zitadel ships before the upgrade, tokens are unverified | Medium (provisioning checklist item could be skipped) | High (auth bypass) | JWKS verification is a hard gate in the Zitadel provisioning checklist (ADR-0011/ADR-0025); startup guard: refuse `NODE_ENV=production` with `DEV_JWT_SECRET` set; OIDC path fails closed (no `enterpriseId` claim ⇒ 401) |
| **RLS misconfiguration** — new tenanted table added without RLS enablement, or table owner bypass | Medium (schema evolution) | High (cross-tenant leak) | `TENANT_TABLES` registry in `packages/db/src/schema.ts` + migration-time assertion that every tenanted table has the `enterprise_isolation` policy (`FORCE ROW LEVEL SECURITY`); contract tests assert cross-tenant queries return zero rows; schema-review checklist in PR template |
| **Docker directive regression** — a future contributor adds a `Dockerfile`/compose file out of habit | Medium | Medium (user-directive violation, repo pollution) | CI check fails on any `Dockerfile`/`docker-compose*`/`*.dockerfile`; ADR-0001 cited in CONTRIBUTING; provisioner is the blessed path (`scripts/provision` + `infra/native/` + systemd) |
| **Native provisioner drift across OS versions** — apt packages (PG, Valkey, Asterisk) vary by distro release | Medium | Medium (broken `make setup`) | Pinned distro baseline (Debian 13 bookworm-era, see `scripts/provision/debian.sh`); component binaries pinned by version+hash in `infra/native/`; `make setup` smoke-tested per wave; ansible/terraform under `infra/` as the fleet-grade path |
| **Meilisearch/ClickHouse tenant scoping** — dedicated datastores don't inherit Postgres RLS | Medium (query bugs) | High (cross-tenant analytics/search leak) | Server-side enterprise filter mandatory (never trust client filters, ADR-0009/ADR-0005); integration tests assert tenant isolation on search + analytics endpoints; index/table naming carries enterprise_id |
| **Valkey durability** — BullMQ jobs lost on restart if persistence (AOF) unconfigured | Medium | Medium (job loss, workflow gaps) | systemd unit ships with AOF + appendfsync config; Temporal (ADR-0007) carries the truly durable workflows; BullMQ reserved for idempotent batch work |
| **ARI credential exposure** — Asterisk ARI rides basic auth; the password sits in cleartext in `/etc/asterisk/ari.conf` (Asterisk requirement); a leak exposes call control + recording | Medium (mis-config / repo commit) | High (call hijack, recording theft) | ARI binds loopback only (`bindaddr = 127.0.0.1:8088`, enforced by `infra/asterisk/provision/asterisk.sh`); password env-templated (`ARI_PASSWORD`), never committed — repo ships a placeholder only; any wider bind must be RFC1918 + firewalled, TLS-terminated via Caddy (ADR-0013/ADR-0026); `0644 asterisk:asterisk` ownership |
| **Recording privacy** — call recordings are sensitive audio (PII); plaintext storage or over-broad access leaks conversations | Medium (until pipeline lands) | High (legal exposure, tenant trust) | Object storage + short-lived signed URLs by design (ADR-0028, 1h expiry, RLS-scoped metadata); encrypt at rest (Garage SSE) + per-role access before the MixMonitor pipeline ships; consent announcement on recordings (spec A1.2) recorded in call metadata; retention policy in the recording lifecycle (ADR-0028 consequence) |
| **TRAI DND / UCC enforcement** — dialing DND-registered numbers or outside the calling window invites complaints and regulator action | Medium (registry is manually seeded today) | High (complaints, fines, number blacklisting) | `dnd_registry` (channel call/all) excluded in `dialer/next`; calling window 09:00–21:00 IST enforced in `sortDialerCandidates` (ADR-0029, override is explicit); broadcast path already keeps `consent_ledger` opt-out ledger from P2 (A2.4); TRAI DND-list ingestion + per-enterprise window config are future work (ADR-0029 consequences) |

## Review cadence

- Every build wave (A1–A8): re-score likelihoods, add wave-specific risks.
- Every dependency bump: license allowlist check (CI) + this register.
- Before first public release: rotate TeleCRM.mcp token, scrub secrets, publish scrubbed `.env.example`.
- Quarterly: TeleCRM parity re-check (risk: API drift).

*Register format: table-first; each row maps to at least one ADR in [docs/DECISIONS.md](DECISIONS.md).*
